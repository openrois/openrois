## [Unreleased]

### Changed

- **Breaking:** a session must send `rois.system.connect` before anything else. Every other request before it, and after `disconnect`, is answered with ERROR. A parent engine connects to each child engine before it reads its profile.
- **Breaking:** every Command interface operation needs a bind from the calling session, on every component it names. `execute` refuses a sequence that names an unbound component with ERROR before anything runs, and `get_parameter` and `set_parameter` on an unbound component answer ERROR. An actuation component takes one bind at a time, and a second session gets OUT_OF_RESOURCES. Sensing and function components, and components declared without a RoSO function, take one bind per session, so several applications share them.
- **Breaking:** `release` drops the caller's bind and aborts the caller's commands still running on that component, which complete with ABORT. `disconnect`, and a client connection that closes, release every bind and subscription of the session and abort every sequence it had running. A running `start` is halted with the component's `stop` handler. Other sessions' binds and commands are untouched. A gateway holds one bind in each child engine for all its clients, so it halts an aborted command in the child, with `stop` and then `release`, only when no other client still holds the component, and otherwise the command runs on there.
- **Breaking:** the engine a client calls assigns every command id, as `engine_id/cmd-1`, and ignores the ids a client sends. The `execute` result carries the sequence with the assigned ids, and every `rois.command.completed` names them. A parent engine names the ids itself, and the engines below it reuse them.
- **Breaking:** a `ConcurrentCommands` item holds branches: the branches run at the same time, each branch runs its commands in order, and the next item waits for every branch. A flat `command_list` still reads as one branch per command. A command that ends other than OK aborts the rest of its branch and every item after it.
- **Breaking:** the `timeout` of a command profile judges only whether the command started, counted from its receipt (Table 8.21). A command not started in time, such as a `start` still waiting for the start before it to unwind, or a command a child engine does not accept in time, completes with TIMEOUT. A command that started runs as long as its handler does.
- **Breaking:** `set_parameter` applies the values before it replies, and then sends `rois.command.completed`, so a command sent after the reply sees them, through a gateway too. A parameter the profile marks `read_only`, or one it does not list, is refused with BAD_PARAMETER and none of the values is applied. Inside `execute`, a `set_parameter` command behaves the same.
- **Breaking:** `component_status` is answered for the asking session. BUSY means another session holds the bind of an actuation component, and no longer that a command runs. A component is UNINITIALIZED until its resources are open and it has connected, and a raised ERROR comes above a raised WARNING, which comes above the lifecycle.
- **Breaking:** a second `subscribe` with the same event type and condition from the same session returns the existing `subscribe_id`.
- **Breaking:** `stop` on a RoIS_Common component that is not started completes OK without running the component's `stop` handler.
- **Breaking:** `WsClient` no longer spins the rclpy node a component keeps in `_node`. Components that talk ROS 2 share an `RclpyExecutor` from `openrois-components-core`, a resource the engine opens before they connect and closes after they disconnect.
- **Breaking:** the component contract changed. `set_parameter` returns the result and how the change ended, `query` and `subscribe` take the arguments of the message, a source receives an error callback through `on_error`, and cancelling `run` aborts the command. `LocalComponent` gains `rois_resources`, and `rois_query` and `rois_subscribed` take arguments.

### Added

- Errors and statuses, design C. A component raises WARNING or ERROR with `raise_status` and withdraws it with `clear_status`, and so does a resource it shares with other components. Each raise that changes what a component reports is an error: the engine assigns it an id such as `robot/err-4`, sends `rois.system.notify_error` with COMPONENT_INTERNAL_ERROR, or COMPONENT_NOT_RESPONDING when a resource raised it, and answers `get_error_detail` with `component_ref`, `status`, `message` and `time` until the status clears. The error goes to the sessions that hold a bind or a subscription on the component, and to a parent engine, which passes it up under the same id. A raised ERROR refuses the component's commands and queries and holds back its events until it clears.
- `Engine.raise_status` and `Engine.clear_status`, for an error of the engine itself. It reaches every connected session as ENGINE_INTERNAL_ERROR, and a SystemInformation component reports it as `engine_status`.
- Resources: the engine opens each resource the local components share once, before the first component that uses it connects, and closes it after the last one has disconnected. A resource whose `open()` fails leaves its components in ERROR, never connected.
- The RoIS_Common default for every local component whose profile includes RoISCommon. A component is started from the moment a `start` arrives until `stop`, or until that start ends other than OK. On a component not started, `suspend`, `resume` and `stop` complete OK and run no handler, except that a `stop` while a cancelled `start` still unwinds cancels it again. `suspend` holds `start` and every other function command of the component, directly or in a sequence, until `resume`. A held command that passes its profile timeout ends with TIMEOUT, `set_parameter` applies at once, a running command keeps running, and the component's events are dropped while it is suspended. `stop` ends the suspension, and the commands it held end with ABORT. A handler runs in addition: `suspend`'s after the hold, `resume`'s before the release. A `suspend` that fails lifts its hold, and a `resume` that fails keeps it. `component_status` does not change.
- The adapter configuration loader, `openrois.engine.config`. An adapter declares its settings as a subclass of `AdapterConfig`, with one section per component, and `load_adapter_config` reads them from the defaults, then `adapter.yaml` (named by `--config` or `OPENROIS_ADAPTER_CONFIG`), then the environment, then the flags, each overriding the one before. The environment and the flags set only `gateway_url`, `engine_id`, `robot_address` and `log_level`, as `OPENROIS_ADAPTER_*` variables and `--gateway-url`, `--engine-id`, `--robot-address` and `--log-level`. An unreadable file or an invalid setting raises `ConfigError`, which names each invalid setting. `load_config` is the loader behind it, for any model and environment prefix, and the gateway reads its own settings with it.
- Arguments on queries and events. A query or a subscribe gives the arguments of its message in the condition, for example `stream_id = 'audio-1'` for `get_stream_status`, and the engine passes them to the component. An event a component emits about some argument values reaches the subscriptions whose arguments match them.

### Removed

- **Breaking:** the `rois.stream.*` reservation. Streaming components carry their messages on the Command, Query and Event interfaces, and a `rois.stream.*` method is as unknown as any other name outside the catalog.

## [0.1.0a1] - 2026-10-08

### Added

- `Engine`, the recursive RoIS HRI Engine. It answers the 16 methods of the RoIS method catalog for the components it hosts in its process and for those of its child engines, so one class serves an adapter, a gateway and a middle tier. It selects components by CQL2-Text condition, aggregates the profiles of its child engines as sub profiles, reserves actuation components for the session that binds them, and routes every id to the engine that assigned it.
- Command sequences: `execute` checks the whole sequence first, then runs the items in order with their `delay_time`, runs the commands of a `ConcurrentCommands` item at the same time, each after its own `delay_time`, stops at the first command that ends other than OK and completes the commands after it with ABORT. A delay counts once however deep the component. Every command sends one `rois.command.completed` to the session that started it, and `get_command_result` reads its results.
- Engine-assigned ids that start with the engine id, `engine_id/sub-1` for example, so a service application or an agent sees which engine owns each subscription, event and set_parameter command. `execute` refuses a client's command id in that namespace.
- `LocalComponents`, which hosts components written with `openrois-components-core` or of the same shape (`LocalComponent`). It stores their parameters from the profile defaults, runs the `@on_set_parameter` hook, answers `component_status` from the state of each component, applies the timeout of each command profile, aborts a running `start` on `stop` or on a new `start`, and keeps events for `get_event_detail` until they expire. Components emit events from any thread.
- `ChildEngine`, which reaches a child engine with the same catalog requests a client sends, reads its profile again when the child sends `rois.system.profile_changed`, checks the engine ids of every profile and the ids of every reply, and ends a subscription whose reply came after its caller stopped waiting.
- `ComponentContract`, the interface behind which the components of an engine live, and `Session`, a client of an engine or its parent engine.
- `WsServer`, which serves child engines on `/adapter` and clients on any other path of one port. It discovers each child engine with `rois.system.get_profile`, refuses an empty, slashed or duplicate engine id and a ref the child does not own with close code 1008, at discovery and when the child's profile changes, and releases a client's bindings and subscriptions when it disconnects. Each request runs in its own task, and a reply always goes out before the notifications it causes. It answers PARSE_ERROR, INVALID_REQUEST, METHOD_NOT_FOUND, INVALID_PARAMS with the issues as data, and INTERNAL_ERROR, binds loopback by default, and closes every connection with code 1001 when it stops.
- `WsClient`, which connects an adapter to a gateway, serves it through a trusted session, spins the rclpy nodes of its components when rclpy is installed, and reconnects with a growing delay. When it stops, it stops the engine while the rclpy nodes still spin, so a component can halt its robot over ROS 2.
- Type information for every public name (`py.typed`), checked with mypy in strict mode.
